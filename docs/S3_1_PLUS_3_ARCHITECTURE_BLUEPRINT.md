# 智学探险家 · 1+3 架构蓝图：容器与内容分离的世界引擎设计

## 1. 蓝图目标

S3 阶段的目标不是继续堆叠单个关卡，而是建立一套可长期扩展的“世界引擎”。

这套引擎要让《智学探险家》从“一个个独立页面”升级为“一个可持续生长的数学冒险世界”。

核心设计是 `1 + 3`：

- `1`：一个稳定的世界容器
- `3`：三类可替换、可扩展、可复用的内容模块

世界容器负责承载体验、状态、节奏和导航。

内容模块负责提供剧情、数学动作、视觉资产和关卡数据。

二者必须分离，避免每做一个新岛就重新写一套页面和流程。

## 2. 总原则

S3 架构遵守以下原则：

1. 容器稳定，内容可变
2. 游戏动作优先，题目表达后置
3. 世界叙事统一，岛屿内容差异化
4. UI 组件复用，关卡配置驱动
5. 每个数学概念都必须变成可操作的冒险行为

S3 不允许把关卡做成“选择题 + 游戏皮”。

S3 的数学学习必须发生在孩子的游戏操作中。

## 3. 1：世界容器

世界容器是 S3 的长期主框架。

它负责：

- 世界地图
- 岛屿入口
- 当前任务
- Nova 陪伴
- 进度保存
- 奖励反馈
- 关卡切换
- 完成后的下一步推荐

世界容器不直接写死某一座岛的剧情、题目和文案。

世界容器只知道：

- 当前在哪个岛
- 当前处于哪个阶段
- 当前需要加载哪份内容配置
- 当前孩子做了什么操作
- 当前世界应该如何反馈

世界容器像一个舞台。岛屿内容像剧本和道具。

舞台保持稳定，剧本和道具可以不断替换。

## 4. 3：三类内容模块

### 4.1 Narrative Module：叙事模块

叙事模块负责回答：

- 这座岛为什么变暗？
- 谁被瞌睡迷雾困住了？
- 孩子要帮助谁？
- Nova 在这一关中的角色是什么？
- 成功后世界发生什么变化？

叙事模块包括：

- 岛屿名称
- 岛屿目标
- 入口文案
- Nova 台词
- 阶段标题
- 成功反馈
- 复盘总结
- 完成页文案

叙事模块必须遵守 `docs/S3_NARRATIVE_BIBLE.md`。

叙事模块不能出现攻击性表达，不能把数学包装成战斗武器。

### 4.2 Math Action Module：数学动作模块

数学动作模块负责回答：

- 孩子实际要做什么操作？
- 这个操作对应哪个数学概念？
- 操作成功时，世界如何反馈？
- 操作失败时，Nova 如何温和引导？

数学动作不是传统题目外壳。

例如 S3E1 中：

- 数学概念：凑成 10
- 游戏动作：拖动或选择两个数字能量球
- 成功反馈：能量球合成星光，迷雾散开，小精灵醒来
- 失败反馈：能量球轻轻弹回，Nova 提醒“再看看它们合起来是不是 10”

数学动作模块可以扩展为：

- 凑十
- 找规律
- 分拆数字
- 比较大小
- 配对
- 排序
- 分类
- 路径推理

每一种数学动作都应该有自己的交互模型，而不是全部退化成选择题。

### 4.3 Presentation Module：表现模块

表现模块负责回答：

- 这一关使用什么背景？
- 哪些角色出现？
- 哪些机关变化？
- 成功时哪里变亮？
- 失败时如何温和反馈？
- 移动端和桌面端如何呈现？

表现模块包括：

- 背景图
- 角色图
- 可交互物件
- 动效
- 音效
- 成功/失败视觉状态
- 移动端布局规则

表现模块不能把文字烘焙进图片。

所有文字必须由代码叠加，方便低龄文案迭代和多关卡复用。

## 5. 容器与内容分离规则

S3 开发中必须区分“容器问题”和“内容问题”。

容器问题包括：

- 阶段流转
- 布局骨架
- 进度存储
- 通用按钮
- 通用反馈
- Nova 通用入口
- 通用完成页结构

内容问题包括：

- 某座岛的剧情
- 某座岛的题库
- 某座岛的文案
- 某座岛的视觉资产
- 某座岛的数学动作参数

禁止把内容问题写死进容器。

例如：

- 不要在 Runner 里硬编码“能量树”
- 不要在通用按钮里硬编码“森林宝箱”
- 不要在完成页通用结构里硬编码某座岛的结果文案

这些内容必须来自配置、题库或对应岛屿的内容模块。

## 6. 推荐目录方向

S3 可以逐步演进为以下结构：

```text
app/
  adventure/
    forest-rpg/
      page.tsx

components/
  adventure/
    WorldAdventureShell.tsx
    NovaCompanionPanel.tsx
    AdventureHeader.tsx
    AdventureCompletePanel.tsx
    math-actions/
      MakeTenAction.tsx
      NumberPatternAction.tsx

lib/
  s3/
    worldTypes.ts
    worldEngine.ts
    islands/
      forestRpg.ts
    questionPools/
      makeTenPools.ts

public/
  assets/
    s3/
      forest-rpg/
```

这不是一次性重构要求，而是 S3 后续演进方向。

当前阶段应优先保持最小改动，在现有代码上逐步抽离。

## 7. S3E1：森林小路 · 星光唤醒

S3E1 是第一座真正验证 `1 + 3` 架构的样板关。

名称：`森林小路 · 星光唤醒`

核心体验：

孩子和 Nova 来到一条被瞌睡迷雾挡住的森林小路。

小精灵睡着了，星光碎片散落在路边。

孩子需要把两个数字能量球合成 10。

如果合成 10：

- 能量球发光
- 迷雾散开
- 小精灵醒来
- 森林变亮
- Nova 鼓励孩子

如果没有合成 10：

- 能量球轻轻弹回
- 迷雾没有散开
- Nova 温和提醒
- 孩子可以继续尝试

这一关的重点不是答题正确率，而是让孩子感到：

“我动手做了一件事，数学让世界变亮了。”

## 8. 状态流建议

S3E1 可采用轻量状态流：

```text
intro
  -> explore
  -> makeTenAction
  -> wakeSpirit
  -> reflection
  -> complete
```

每个状态只做一件事：

- `intro`：进入森林小路，看到迷雾和沉睡小精灵
- `explore`：Nova 提醒观察数字能量球
- `makeTenAction`：孩子操作两个数字合成 10
- `wakeSpirit`：小精灵醒来，森林局部变亮
- `reflection`：Nova 总结今天使用的数学力量
- `complete`：获得星光碎片或唤醒纪念

状态流可以复用现有关卡节奏，但要避免把所有互动压成题目按钮。

## 9. 数据配置建议

S3 岛屿配置至少应包含：

```ts
type S3IslandConfig = {
  id: string;
  name: string;
  route: string;
  narrative: {
    introTitle: string;
    introLine: string;
    goal: string;
    successLine: string;
    completeLine: string;
  };
  mathAction: {
    type: "make-ten" | "number-pattern" | "split-number";
    target?: number;
    pairs?: Array<[number, number]>;
  };
  presentation: {
    background: string;
    nova: string;
    sleepingSpirit?: string;
    awakeSpirit?: string;
    darkState?: string;
    lightState?: string;
  };
};
```

实际实现时可以根据现有代码渐进拆分，不要求一次到位。

## 10. Nova 在 1+3 架构中的位置

Nova 属于世界容器的一部分，也是叙事模块的重要角色。

Nova 的通用能力由容器提供：

- 陪伴入口
- 提示层级
- 鼓励反馈
- 复盘总结
- 错误时温和提醒

Nova 的具体台词由内容模块提供。

同一个 Nova，在不同岛屿中可以说不同的话，但角色定位不能变：

- 不抢答
- 不责备
- 不替孩子完成核心动作
- 先鼓励观察
- 再给一点线索
- 最后才总结方法

## 11. 移动端优先规则

S3 的核心体验必须优先适配手机。

移动端规则：

- 第一屏要看到当前任务
- 主要互动不能被 Nova 面板挤压
- 文字短，按钮明确
- 主要操作区尽量单列
- 完成反馈要大、亮、清楚
- 不出现横向溢出
- 不让关键按钮掉到很深的位置

桌面端可以更丰富，但不能反过来把移动端压成缩小版桌面。

## 12. 资产规则

S3 资产必须遵守项目视觉资产规则：

- 正式视觉资产使用 GPT Image 生成
- 图片中不得烘焙文字、数字、按钮
- 文案由代码叠加
- 资产命名与 `lib/*Assets.ts` 对应
- 不随意移动或重命名现有资产

S3 推荐资产方向见 `docs/S3_NARRATIVE_BIBLE.md`。

## 13. 验收标准

一个 S3 关卡只有同时满足以下条件，才算符合 `1 + 3` 架构：

- 有明确的世界处境
- 有符合叙事圣经的非暴力目标
- 有孩子实际操作的数学动作
- 有从暗到亮、从沉睡到唤醒的反馈
- Nova 是伙伴而不是普通提示按钮
- 关卡文案来自配置，不硬编码进通用容器
- 移动端第一屏能看懂下一步要做什么
- 完成页能让孩子感到“我点亮了这个地方”

## 14. 后续开发要求

所有 S3 开发任务必须先读取：

1. `docs/S3_NARRATIVE_BIBLE.md`
2. `docs/S3_1_PLUS_3_ARCHITECTURE_BLUEPRINT.md`

后续新增 `/adventure/forest-rpg` 时，必须遵守本蓝图：

- 先定义内容模块
- 再接入世界容器
- 不把岛屿内容硬编码进通用 Runner
- 不把 S3 做成选择题换皮
- 数学动作必须尽量成为游戏动作

如果短期内必须借用现有 `AdventureRunner`，也要把 S3 专属内容放在配置层，为后续抽离世界容器留出接口。
